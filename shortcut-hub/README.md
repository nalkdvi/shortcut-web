# Shortcut Hub

iPhoneの「ショートカット」で作成したiCloud共有リンクを投稿・検索できるWebサイトです。
タイトル、説明、カテゴリ、投稿者名、投稿日をカードで表示します。
1つの機能が複数のショートカットに分かれている場合は、1つの投稿に最大10件のリンクをまとめられます。
リンクごとのボタンから、ショートカットを1つずつ開いて追加できます。
アカウント登録は不要です。投稿時に設定した削除用パスワードで、自分の投稿を削除できます。
ショートカットのファイルは保存せず、共有リンクと紹介文だけを扱います。

## 作ろうと思った目的

便利なショートカットの共有リンクをまとめ、用途に合うものを探せる場所を作ることが目的です。
この制作では、画面・API・データベースをつなぐ基本と、入力を安全に扱う方法を自分で説明できることを重視しています。

## 使用技術と役割

| 技術 | このサイトでの役割 |
| --- | --- |
| HTML | フォーム、検索欄、カードのひな型など、画面の構造を作る |
| CSS | 色、余白、カードの配置、スマートフォン向けの表示を整える |
| JavaScript（Vanilla JS） | 投稿の取得・送信、入力検証、検索、カテゴリ絞り込み、カード表示を行う |
| Node.js | ブラウザーの外でJavaScriptのサーバーを動かす |
| Express | HTMLなどの配信と、GET・POST・DELETEのAPIを担当する |
| SQLite | 投稿を1つのデータベースファイルに保存する |
| better-sqlite3 | Node.jsからSQLiteへSQLを実行する |
| npm | ライブラリのインストールと起動コマンドの管理をする |

追加のフレームワーク、認証ライブラリ、ビルド処理は使用していません。

## 動作環境

- Node.js 22以上（推奨：Node.js 24 LTS）と、同梱されるnpm
- Windows、macOS、Linux
- JavaScriptが有効なブラウザー

Node.jsは[公式サイト](https://nodejs.org/en/download)からインストールできます。
`better-sqlite3`はネイティブモジュールです。対応するNode.js LTSを使うと、通常はビルド済みのものをインストールできます。
対応バイナリーがない環境ではコンパイラーなどが必要になるため、まずNode.jsのバージョンを確認してください。

## インストール方法

ターミナルで、このREADMEがあるフォルダーへ移動します。

```sh
cd shortcut-hub
npm install
```

`package-lock.json`も保管し、同じ依存関係を入れ直したい場合は`npm ci`を使います。
WindowsのPowerShellで`npm.ps1`の実行を禁止するエラーが出る場合は、`npm.cmd install`を使ってください。
Node.jsをインストールした直後は、新しいターミナルを開いてください。

## 起動方法

```sh
npm start
```

ブラウザーで **http://localhost:3000** を開きます。
PowerShellでスクリプトの実行エラーが出る場合は`npm.cmd start`を使います。
停止するときは、サーバーを起動したターミナルで`Ctrl+C`を押します。

初回起動で`data/shortcuts.db`と`shortcuts`テーブルを自動作成します。
最初の投稿は空です。自分のiPhoneからコピーした共有リンクを使って投稿してください。
サーバーを再起動しても、同じデータベースファイルがあれば投稿は残ります。

任意で、環境変数`PORT`でポート番号、`DATABASE_PATH`で保存先を変更できます。
`.env`を自動で読み込む仕組みはありません。環境変数はターミナルや公開先の設定で指定します。

```powershell
# Windows PowerShellでの例
$env:PORT = "3001"
$env:DATABASE_PATH = "D:/shortcut-hub-data/shortcuts.db"
npm.cmd start
```

ポートを変更した場合は、表示されたURLを開いてください。
相対的な`DATABASE_PATH`は、`server.js`があるフォルダーを基準に解決します。

## 投稿者による投稿の削除

1. 投稿するときに、削除用パスワードを設定します（8〜128文字）。
2. 削除したいカードの「この投稿を削除」を押し、投稿タイトルと削除対象を確認して、同じパスワードを入力します。
3. 「削除する」を押すと、その投稿がSQLiteと一覧から削除されます。「キャンセル」では削除しません。

複数URLを含む投稿も、カード1枚の単位で削除します。iCloud上のショートカット自体は削除しません。
削除した投稿を戻す機能と、パスワードを再設定する機能はありません。パスワードは投稿者自身で保管してください。
削除用パスワードを設定する前の既存投稿は、そのまま残し、削除ボタンを無効にします。APIでも削除を拒否します。

パスワードは元の文字列では保存しません。Node.js標準の`crypto`を使い、投稿ごとに異なるソルト（ランダムな値）と`scrypt`で照合用ハッシュを作ります。
削除時も同じ方法でハッシュを計算し、一致した投稿だけを削除します。
一覧の取得や投稿成功の返答には、元のパスワードもハッシュも含めません。
パスワードの前後の空白は勝手に取り除かず、入力した値のまま照合します。空白だけの値は許可しません。
公開時はHTTPSを使います。パスワードはブラウザーの保存領域に保持せず、投稿・削除の送信時だけAPIへ渡します。

## データベースとAPI

`shortcuts`テーブルには次の情報を保存します。

| カラム | 内容 |
| --- | --- |
| id | 投稿を識別する自動採番の整数 |
| title | タイトル |
| description | 説明 |
| category | 5種類のうち1つ |
| url | iCloud共有リンク。複数の場合は入力順に改行で区切った文字列 |
| author | 投稿者名。省略した場合は空文字で保存し、画面には「匿名」と表示 |
| created_at | サーバーで記録するUTCの投稿日時。画面では閲覧端末の日時で表示 |
| delete_password_hash | 削除用パスワードのソルトとハッシュ。APIでは公開しない。既存の未設定投稿はNULL |

既存のテーブルに`delete_password_hash`がなければ、起動時に`ALTER TABLE`で追加します。既存の投稿は保持します。
APIでは公開用のカラムだけを指定して取得し、削除用パスワードの設定有無を示す`can_delete`（0または1）も返します。

- `GET /api/shortcuts`：投稿の配列をJSONで返します。新しい日時から並べ、同じ日時ではidが大きい方を先にします。
- `POST /api/shortcuts`：JSONで投稿を受け取り、保存した投稿をステータス`201`で返します。
- `DELETE /api/shortcuts/:id`：JSONの`password`で指定した投稿の削除用パスワードを照合します。成功は`200`、パスワード不一致は`401`、未設定の既存投稿は`403`、該当なしは`404`です。

POSTの入力項目は次のとおりです。

```json
{
  "title": "集中タイマー",
  "description": "勉強を始めるときに使うタイマーです。",
  "category": "勉強",
  "url": "https://www.icloud.com/shortcuts/0123456789abcdef0123456789abcdef",
  "author": "学生",
  "delete_password": "example-delete-password"
}
```

上記URLは形式を示す例です。実在するショートカットを示していません。
`author`は省略できます。それ以外は必須です。
`delete_password`は8〜128文字で、空白だけの値は不可です。公開資料の例と同じ値をそのまま使わず、自分で決めた値を設定してください。
複数の共有リンクは、フォームのURL欄に1行に1つずつ入力します（1〜10件）。
空行と各行の前後の空白は取り除きます。1件でも不正なURLがあれば投稿全体を保存しません。

```text
https://www.icloud.com/shortcuts/0123456789abcdef0123456789abcdef
https://www.icloud.com/shortcuts/11111111111111111111111111111111
https://www.icloud.com/shortcuts/22222222222222222222222222222222
```

上記も形式の例です。APIでは`url`を改行文字（`\n`）で区切った文字列として送ります。
SQLiteの`url`欄にその文字列を保存し、画面では`split`で分けてリンクごとのボタンを作ります。
新しいテーブルやカラムは追加せず、従来の1件のURLも同じ処理で表示します。
複数の場合は「ショートカット1を開く」「ショートカット2を開く」のように、入力順の番号を付けます。
各ボタンは対応するiCloud共有ページを新しいタブで開きます。必要なショートカットを1つずつ追加してください。

カテゴリは「便利ツール」「勉強」「仕事効率化」「エンタメ」「その他」から選びます。
エラーは`{"error":"日本語のメッセージ"}`というJSONで返します。
主なステータスは、入力不正`400`、大きすぎるデータ`413`、JSON以外の送信`415`、回数制限`429`です。
削除APIは投稿APIとは別に、同じIPからの試行を10分間で5回までに制限します。失敗した認証や不正JSONも数えます。
削除はその投稿のパスワードの照合後に、`DELETE FROM shortcuts WHERE id = ?`で対象の1行だけを消します。

## 投稿から保存、表示までのデータの流れ

1. ブラウザーがExpressからHTML・CSS・JavaScriptを受け取ります。
2. `app.js`が`fetch`で`GET /api/shortcuts`を呼びます。
3. ExpressがSQLiteを`SELECT`し、投稿の配列をJSONで返します。
4. ブラウザーが配列からカードを作り、`textContent`でタイトルなどを表示します。
5. 投稿するときは、フォームの値をブラウザー側で検証し、JSONにして`POST /api/shortcuts`へ送ります。
6. Expressが投稿回数を確認し、受け取った値をもう一度検証します。
7. すべてのURLの検証に通ったら、URLを改行でまとめ、プレースホルダーを使った`INSERT`で1つの投稿としてSQLiteに保存します。
8. サーバーが保存結果を返し、ブラウザーが新しい投稿を一覧に反映します。

検索とカテゴリ絞り込みは、取得済みの配列に対するJavaScriptの`filter`で行います。
タイトルまたは説明がキーワードを含み、選択したカテゴリにも一致する投稿を表示します。
検索のたびにサーバーと通信しないので、処理の役割を追いやすい構成です。
ほかの人の新しい投稿を取得したいときは、ページを再読み込みします。

## 工夫したポイント

- 画面とサーバーで、必須項目・文字数・カテゴリ・URLを検証します。ブラウザーの検証は回避できるため、サーバーでも確認します。
- URLは`https://www.icloud.com/shortcuts/`と32桁の16進数IDの形に限定し、`URL`でプロトコル、ホスト名、パスも検証します。認証情報、ポート、追加パス、クエリ、フラグメントは許可しません。
- 複数URLも1件ずつ同じ方法で検証し、入力順に個別のボタンを作ります。
- URLの形式を検証する仕組みです。リンク先の実在・削除状況や、ショートカットの動作までは確認していません。
- SQLに入力を文字列連結せず、`?`へ別の値として渡します。SQLの命令と投稿の内容を分けて扱えます。
- 投稿をHTML文字列として挿入しません。`<script>`などを含む文章も、文章として表示します。
- IPごとに投稿の試行を10分間で5回までに制限します。入力エラーも回数に含め、超えたら`429`と`Retry-After`を返します。
- 送信中はボタンを無効にし、失敗したときは入力を残します。取得失敗時には再試行できます。
- 一覧を取得できるまでは投稿を無効にし、遅い一覧取得が投稿直後の表示を上書きしないようにしています。
- 削除は投稿ごとの削除用パスワードで保護し、確認画面から実行します。APIが成功するまでカードは一覧から消しません。
- 白を基調に青・紫を使い、スマートフォンでも押しやすいボタンと余白を確保します。
- 重要な処理に短い日本語コメントを付け、必要なライブラリを2つに絞っています。

回数制限の記録はサーバーのメモリに保持します。再起動するとリセットされ、複数サーバー間では共有されません。
プロキシ経由で公開すると、設定によっては全員が同じIPとして扱われます。
現在は偽装ヘッダーを信頼しない既定値です。公開先の仕様を確認して、必要な場合だけExpressの`trust proxy`に信頼するプロキシを指定してください。

## 自分で動作を確認する手順

1. 起動して、投稿前の空の一覧が表示されることを確認します。
2. iPhoneのショートカットアプリから共有リンクをコピーし、タイトル・説明・カテゴリと一緒に投稿します。
3. 一覧に追加され、再読み込みしても投稿が残ることを確認します。
4. 2件目を別カテゴリで投稿し、新しい投稿が先に表示されることを確認します。
5. タイトル、次に説明に含まれるキーワードで検索します。
6. カテゴリと検索を組み合わせ、存在しないキーワードでは該当なしの表示になることを確認します。
7. 不正なURL・空白だけの必須項目が送信できないことを確認します。
8. 「ショートカットを開く」が入力したiCloudリンクへ移動することを確認します。
9. ウィンドウ幅を狭め、フォームやカードが画面からはみ出さないことを確認します。
10. サーバーを停止して再起動し、保存した投稿が残ることを確認します。
11. 3件の共有URLを改行して1回で投稿し、1枚のカードに3つのボタンが表示されることを確認します。それぞれが入力順のリンクに対応していることを確認します。
12. 2件目だけを不正なURLにして投稿し、何件目が不正か表示され、投稿が追加されないことを確認します。
13. 確認用の投稿で削除画面を開き、キャンセルや間違ったパスワードでは投稿が残ることを確認します。正しいパスワードでは対象だけが削除され、再読み込み後も戻らないことを確認します。

回数制限が出たら、表示の案内に従って待ってください。
ブラウザー側だけでなくサーバー側の検証も確認するときは、開発者ツールやHTTPクライアントから不正なJSONを送って、`400`になることを確かめます。

## SQLiteを公開環境で使う場合の注意点

SQLiteのデータは、サーバー上の`shortcuts.db`というファイルに保存されます。
公開先で再起動や再デプロイによりローカルファイルが消えると、投稿も消えてしまいます。
永続ディスクを利用できるNode.jsの実行環境を選び、`DATABASE_PATH`でそのディスク上のファイルを指定してください。
このままでは、静的サイト専用の公開先や、ファイルが一時的にしか残らないサーバーレス環境には対応できません。

保存先には書き込み権限が必要です。小規模な単一サーバーでの運用を想定し、複数インスタンスそれぞれに別のDBを作らないようにします。
バックアップはアプリを停止してデータベースファイルをコピーする方法が分かりやすいです。
本番のデータベースはGitへ登録せず、バックアップは公開ディレクトリの外に保管してください。
